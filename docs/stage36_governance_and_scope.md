# Stage 36 — Governance, Safety Invariants, and Scope Specification

**Component:** Component 3 — AI/NLP-Based Language Simplification  
**Scope:** Sinhala (`si`, `si-LK`, script `Sinh`) Output Validation, Risk Routing, Safe Abstention, and Governed Fallback  
**Prerequisite Anchor:** `stage-35-complete-v7` at commit `cd86a6b0aff2d07d7d0c4f8079f10e9833b5b3d0`  

---

## 1. Scope and System Boundary

Stage 36 provides an automated, fail-closed validation and governed fallback pipeline for candidate text simplifications generated by any governed provider (`C0_RULE_BASELINE`, `C1_GEMINI_EXPERIMENTAL`, `C2_MT5_EXPERIMENTAL`, `C3_MBART_EXPERIMENTAL`).

### Included Scope
1. **Provider-neutral envelope validation:** Strict schema validation with lineage rights and execution receipts.
2. **Deterministic Linguistic & Orthographic Gates:**
   - Unicode serialization, NFC compatibility and script-validation gate ($V_1$) without silently rewriting provider output.
   - Structural length bounds ($V_2$) preventing length explosions or severe truncation.
   - Three-tier protected-span integrity ($V_3$): Declared (Hard Gate), Deterministic (Hard Gate), Inferred (Review Gate).
   - Polarity, negation, and numerical fidelity ($V_4$).
   - Omission, unsupported insertion, and hallucination risk ($V_5$).
3. **Automated Diagnostic Proxies:**
   - Coarse semantic-risk proxy diagnostic ($V_6$) using character n-gram Jaccard.
   - Grammaticality and orthography proxy ($V_7$) enforcing virama consistency and delimiter balance.
   - Simplification gain telemetry ($V_8$).
4. **Governed Fallback Engine:**
   - Fixed 9-tier precedence disposition assignment.
   - Bounded fallback ladder ($\text{Primary} \rightarrow \text{C0} \rightarrow \text{Unchanged Source} \rightarrow \text{Safe Abstention}$) with maximum depth 3.
5. **Protected Storage and Cryptographic Audit:**
   - Access-controlled filesystem root outside git repository.
   - Append-only hash-chained HMAC audit logging (`stage36-public-provenance-v1`).

### Excluded Scope
1. Live cross-model empirical superiority claims.
2. Silent mutation or rewriting of candidate outputs.
3. Automated approval for direct or unsupervised child delivery.
4. Overriding hard gate failures using automated similarity metrics.

---

## 2. Mandatory Governance Invariants

1. **Fail-Closed Default:** Any uncertainty, validator exception, or configuration mismatch defaults to safe abstention (`REJECTED_NO_OUTPUT` or `MANUAL_REVIEW_NO_OUTPUT`).
2. **Immutability of Child Safety Flags:** `approved_for_child_delivery` and `approved_for_unsupervised_child_delivery` must strictly evaluate to `false` for all automated outputs.
3. **Candidate Immutability:** Candidate text is evaluated as received. NFC compatibility is validated without silent in-place modification.
4. **Execution vs. Disposition Decoupling:** Every evaluation produces an `execution_outcome` (`COMPLETED` or `FAILED_INTERNAL`) and exactly one terminal `candidate_disposition` if completed.
5. **Bounded Depth:** Fallback depth is capped at 3 transitions with zero cyclic loops.
6. **Zero Database Impact:** Automated validation tests must never modify or lock `backend/adaptive_learning.db`.
